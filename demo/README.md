# PIPER 抛接 Demo：新前端（MIT 监视 + 主从遥操）

独立于 现有控制台工程（piper-workspace） 控制台，**不修改它的任何文件**。只复用它的两样只读资源：URDF 模型/网格（`public/model/piper`）和 `configs/piper.json`（底座位姿、MIT 参数）。

## 启动

只读（默认，不发送任何 CAN 帧）：

```bash
ssh -o ExitOnForwardFailure=yes -L 8071:127.0.0.1:8071 <user>@<host> 'cd ~/jeff_piper_catch/demo && DEMO_ALLOW_CONTROL=0 exec <python-with-piper_sdk> -m uvicorn backend.app:app --host 127.0.0.1 --port 8071'
```

浏览器打开 http://127.0.0.1:8071 。关掉这条 ssh 命令服务就停止。

解锁控制（会让臂运动，只在有人现场、主臂已上电、急停可达时使用）：把 `DEMO_ALLOW_CONTROL=0` 改成 `DEMO_ALLOW_CONTROL=1`。

## 功能

- **URDF 预览**：两条从臂实测姿态（含夹爪开度和 TCP 标记）；主臂以半透明叠加在对应从臂底座上，用来目视对比主从姿态。
- **MIT 数据**：四条臂（左/右 × 从/主）各自的关节角、速度、电机电流、力矩反馈、静态重力预测（与控制台 MIT 前馈同一公式，已与控制台实现逐点比对，200 个随机姿态误差为 0）、两者差值、电机/驱动温度、电压、使能、控制/运动模式（MIT = 6）、状态、反馈频率和延迟；10 s 曲线图（关节角、电流、力矩、残差），悬停读数，图例可开关。
- **主从遥操（软件 MIT）**：见下。

## 主从遥操

复现控制台的 MIT 生命周期：固件版本 ≥ S-V1.8-8 → 保持当前位置使能 → `MotionCtrl_2(1, 6, 0, 0xAD)` 进入 MIT 并等固件反馈 `mode_feed == 6` → 200 Hz 发送 `JointMitCtrl`（kp=10、kd=0.8，不可在线修改；力矩前馈为静态重力，腕部电机 ÷0.813252，限幅 ±16）→ 退出时回到 MOVE J 位置保持并等固件确认。夹爪每 4 个周期按主臂开度跟随。

安全层（均有单元测试，见 `tests/`）：

1. 服务默认只读；控制接口在 `DEMO_ALLOW_CONTROL=0` 时返回 403。
2. 预检：从臂/主臂反馈新鲜、从臂状态正常、总线上没有别的控制者、主从偏差 ≤ 6°、主臂姿态 TCP 高度 ≥ 0.05 m、未急停。任一项不过不能启动。
3. 界面心跳：浏览器必须每 100 ms 发心跳，超过 0.5 s 没收到就退出 MIT。
4. 每周期检查：主臂反馈中断（>0.08 s 冻结，0.3 s 结束）、跟随误差 > 12°、关节限位（2° 余量）、TCP 高度下限（冻结目标）、目标速度上限 3 rad/s。
5. 任何故障或停止都以 MOVE J 在**当前实测位置**保持，不会跳向主臂，也**不会失能**；失能只通过"归拢并失能"（先慢速回到 `stow_pose.json` 的真实静止姿态，到位才断电）。
6. 急停按钮 / Esc 键发送固件快速急停并锁存，需人工恢复。

## 测试

```bash
cd demo && python -m unittest discover -s tests -v
```

用模拟臂验证状态机、MIT 进入顺序、kp/kd/力矩/速度边界、跟随精度、各种故障退出路径；**没有在真机上跑过任何会发指令的路径**。

## 已知限制

- 主臂当前未上电，因此遥操的真机行为、主臂叠加显示、对齐柱状图的实时效果都还没有验证。
- 力矩反馈是固件按固定系数换算的值，和重力预测的差值含摩擦与换算误差，只作参考。
- 原有的 native bridge（`piper-*-native-bridge.service`）按 CAN 口名写死了配对，口名变化后会校验失败退出；本服务全部按 USB 序列号解析，不依赖口名。

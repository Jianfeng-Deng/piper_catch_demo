# 项目现状（快照：2026-11-17）

目标：两台 PiPER，**左臂抛、右臂接**瓶子/杯子，主要是展示效果。路线是先把运动控制测清楚（重点是 MIT 模式），再规划抛接轨迹，最后上真机。
**还没有做过一次真机的抛接**；下面的"实测"都是单项测试，"规划"都只是离线仿真。

## 1. 硬件与环境

- 4 条臂：左右各一台**从臂**（被控）和一台**主臂**（遥操用）。每条臂一个 USB-CAN 适配器（gs_usb，1 Mbps）。
- 两条从臂固件 **S-V1.9-0**，夹爪是 **100 mm** 版本。两臂底座相距 0.605 m、并排、朝向相同；URDF 的世界系里 `+x` 指向右臂，`+y` 是臂的前向，`z` 向上。
- 3 台 RealSense D435：1 台固定的 top 相机，2 台腕部相机。
- 一台 Linux 主机（RTX 4090）接着全部设备，**与其他人共用**：同机上还有别人的控制台服务，开始运动前必须确认没有别的程序在往同一条臂发指令。
- **CAN 口名不稳定**（重启或重新枚举后会换），所有代码按 USB 序列号解析；原有的转发服务按口名写死配对，口名一变就校验失败退出。

## 2. 实测结果（真机）

| 项目 | 结果 |
|---|---|
| CAN 反馈 | 关节/夹爪 200 Hz，高速反馈 100 Hz，间隔 std ≈ 0.02 ms，无丢帧 |
| URDF 正运动学 vs 固件末端位姿 | 法兰位置 0.09 mm、姿态 0°（只证明连杆参数与固件一致，不等于绝对精度） |
| 夹爪指令→开始动作 | 均值 29 ms，std 3.6 ms（仅 5 次、空载）；到 50% 行程 81 ms，到 90% 159 ms，稳定 250~270 ms |
| MOVE J（位置模式）速度 | J2 关节速度饱和在约 3.05 rad/s，末端约 1.0 m/s（力臂 0.44 m）——**不够抛** |
| MIT 进入 | 固件在 6~11 ms 内确认 `mode_feed = 6` |
| MIT 保持（准备姿态，15 s） | 平均偏差 ≤ 0.22°（J5 例外：+1.1°，重力模型对 J5 补偿偏小），抖动 std ≤ 0.06°，无振荡 |
| MIT 小幅跟踪（J2） | 增益 1.0~1.07，滞后 19~24 ms，RMS 误差 0.3~0.7° |
| MIT 速度爬升（单关节往返摆动 50°，模型前馈） | J2 稳定到 3.18 rad/s（末端 1.35 m/s），实际到过 3.70；J3 稳定 3.13（到过 3.65）；J5 稳定 3.23（到过 3.76）。"稳定"以跟踪误差 ≤ 5° 为准，**不是硬件上限** |
| 跟踪误差的来源 | 误差 ≈ 关节速度 × 23 ms，主要是纯延迟；把目标提前约 20 ms 应能去掉大部分（**尚未实现/验证**） |
| 相机 | D435 深度/红外 848×480 @ 90 fps 实测 89.8 fps，无丢帧；深色瓶子深度可用（框内有效 87%，左侧边缘有固定空洞）；**透明杯子未测，飞行中的物体未测** |
| 移动到指定位姿 | 左臂以 10% 速度 MOVE J 到斜抛准备位姿，6 s，到位偏差约 0.1°，无故障 |

关键认识：
- **MIT 必须用 `C_PiperInterface_V3`**（V2 不接受 `move_mode=6`，且力矩范围不同）。
- 高速时 kp=10 很软，**必须加逆动力学前馈**（`M(q)q̈ + C + g + 摩擦`，用 MuJoCo 计算），否则加速段误差十几度。
- 固件反馈的"力矩"不是真实关节力矩（J2/J3 只有重力预测的约 0.22 倍），所以页面上"力矩 − 重力预测"的残差只能参考。

## 3. 离线规划（仅仿真）

规划器 `demo/backend/throw.py`：关节空间五次多项式 + FK 得到出手速度 + 无阻力抛物线 + 右臂 IK 接取点 + 逆动力学力矩检查。约束：关节速度/加速度预算、**线上等效力矩 ≤ 11 N·m（线上限幅 16）**、TCP ≥ 0.15~0.18 m、右臂 IK 可解。

- **上抛**（J2/J3/J5 配合，夹爪水平侧抓）：低/中/高 三档，抛高 +12/+18/+25 cm，出手 1.5~2.2 m/s，动作 0.5~0.7 s。第一次不带力矩约束的搜索给出的中/高档需要 18~19 N·m，真机做不到，所以力矩约束是必须的。J3（肘）和 J5（腕）做主要功，J2 只转几度（它承载整条臂的惯量）。
- **斜抛**（起点固定为给定的准备位姿：`J1=-3.1 J2=107.5 J3=-104.4 J4=-3.5 J5=19.7 J6=39.7°`，夹爪 60 mm，TCP 在底座前 0.59 m、高 0.34 m）：J1 向右臂转约 38~45°（末端 -41°~-48°）提供横向速度，J2/J3/J5 展开；仰角 36°/45°，出手约 1.5 m/s，抛高仅 +4/+6 cm，出手到接取 0.16~0.18 s，接取时球速 1.3~1.4 m/s。60° 仰角的方案找不到可行解。
  - 从这个伸展姿态出发，J2/J3 抬臂时末端速度是"向上并**向后**（朝底座）"，所以朝右臂的横向速度必须由 J1 提供。
  - **接取很难**：球到右臂时还有 1.3~1.4 m/s，而夹爪闭合需要 80~160 ms，期间球前进 10~20 cm——右臂需要随球运动，或夹爪加漏斗导向。

没有模拟：空气阻力、瓶身旋转、出手时刻误差（夹爪张开延迟抖动 ±3.6 ms，按 2 m/s 约 ±7 mm）、左右臂碰撞。

## 4. 前端/后端（`demo/`）

- 只读遥测（四条臂的角度/速度/电流/力矩/温度/电压/模式，10 s 曲线）、URDF 预览、手动位姿预览（可粘贴位姿文本、可复制位姿描述）、上抛/斜抛预览。
- 逐步 MIT 测试（固件→保持→小幅跟踪→J2/J3/J5 速度爬升）、**移动到位姿**（慢速 MOVE J）、软件 MIT 主从遥操。
- 单元测试 26 个，覆盖状态机、停止条件、规划器。**主从遥操只在模拟臂上测过，没有在真机上跑过**（主臂当时没有反馈）。

## 5. 安全约定（请保持）

1. 后端默认只读（`DEMO_ALLOW_CONTROL=0`），会动臂的接口在解锁前一律 403。
2. 每次测完**先慢速归拢到保存的静止姿态，到位后才失能**，避免臂掉到桌面上。归拢位姿是臂真实静止时的角度（包含腕部下垂后的位置）。
3. 页面右上角**"急停保持"**（Esc）：立即停止所有 MIT 发送并在当前位置位置保持，**不失能**。固件急停可能失能下坠，只作次要手段。终端备用：`python hold.py`。
4. 会动臂的流程都要求页面持续发心跳（放在 Web Worker 里），超过 1 s 没收到就退出并保持；每个流程有跟踪误差、速度、驱动器故障标志等停止条件。
5. 不要向主臂发指令；发指令前先被动监听总线，发现别的控制者就退出。
6. 不要在 MIT 控制线程里做重计算或写盘（会饿住 SDK 反馈线程，触发 100 ms 的反馈中断保护）：前馈表在进入 MIT 之前算好，分析放到退出 MIT 之后。

## 6. 已知问题与未解决

- 两台主臂当时有电但总线上**完全没有反馈帧**（原因未查清：供电、接线或需要被配置）。
- 夹爪指令需要先使能臂并切到 CAN 控制模式才生效（上电后未使能时不响应）；夹爪反馈单位 0.001 mm 已核对（60→10 mm 的行程读数 49.1 mm）。
- TCP 偏移 0.135 m 是名义值，真实抓取中心**未标定**；相机到机械臂基座的手眼标定**未做**；两臂底座相对位姿未用外部真值验证。
- 左臂最近一次被发现处于**示教模式**且关节使能，J5 电机约 49°C（有人手动拖回的）；继续真机动作前请先重新确认状态。
- 右臂静止姿态略超出软限位（J2 < 0、J3 > 0），不能被命令到那里，保持折叠即可。

## 7. 建议的下一步

1. 把"斜抛·低"在真机上**低速回放、不带出手**（时间拉长 3~4 倍），验证 J1 的速度能力和四关节同时运动的跟踪与力矩；加入约 20 ms 的目标提前量。
2. 单独测 J1 的 MIT 高速能力；右臂的 MIT 基线（保持、小幅跟踪、响应延迟）。
3. 做相机到基座的手眼标定、TCP/抓取中心标定；测透明杯子的深度，必要时改用红外图检测。
4. 设计接取策略（右臂随球运动或漏斗），再加夹爪出手和真实瓶子；最后才考虑视觉闭环修正。
